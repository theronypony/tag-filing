# Tag Filing 2.1.1 — deployment and acceptance tests

Use a **backed-up test copy** of the vault in your deployment environment. Local automated tests validate logic and dialog wiring with Obsidian doubles; the checks below validate real Obsidian behavior. No Docker is required.

1. **Install/upgrade.** For a build awaiting publication, copy its `main.js`, `manifest.json`, and `styles.css` into `<vault>/.obsidian/plugins/inherit-tags/` while the plugin is disabled. After publication, BRAT can update normally using `theronypony/tag-filing`. Keep existing `data.json` and logs. Enable it in Obsidian 1.11.0 or later with Notebook Navigator 3.4.3 enabled. Verify **Tag Filing 2.1.1** appears once. Updating from 2.x must preserve new-note filing, onboarding acknowledgment, converter/exclusion settings and command hotkeys. Updating from 2.1.0 must also preserve the tag-drop toggle and saved choice; upgrading from earlier versions starts tag-drop filing on with **Ask every time**. Fresh installs and upgrades from 1.x should show setup and start with new-note filing off. Reload the vault and confirm no existing notes move.

2. **Set up the new command.** In Settings → Hotkeys, remove Command-N/Ctrl-N from Obsidian's **Create new note** and assign it to **Notebook Navigator: Create new note**. Close setup with **Keep automatic filing off**, then reopen **Tag Filing: Show folder filing setup** and accept **NN command configured — enable filing**. Verify the setting survives reload. Confirm the instructions are clear on every device; the plugin does not change hotkeys.

3. **Create and file notes.** Select `#work`, then `#work/meetings`, and use the NN command. Verify Navigator supplies the tag, the note moves to the full tag path from the vault root, missing parent folders are created, and the editor stays usable. Rename notes and check rapid creation and changing selection while a move is queued. Use distinct filenames or clear previous untitled test notes to avoid intentional collision protection.

4. **Automatic eligibility.** Turn filing off and verify nothing moves. Test folder, property, Tagged/Untagged and tag collection selections after previously selecting a tag; an old tag must not be reused. Run Obsidian's core command with an empty note and confirm this plugin adds no tag or folder move. Editing an existing note's tags must not trigger later refiling. Creating a note during a manual preview/conversion must not auto-file it.

5. **Templates and selected tags.** Test NN creation with untagged templates, templates already containing tags, and a capitalized `Tags` property. When the selected tag is present, file to that selected tag's folder even with additional template tags. Verify cursor placement and the open editor after the move. The destination's template must not be applied again. Check your actual third-party template plugins; delayed templates or early renames can prevent automatic filing.

6. **Exclusions.** Set `Templates, Archive` as excluded folders. Test automatic and manual moves from excluded sources, source descendants, and to excluded destinations. No excluded destination folder should be created. Excluding `Arch` must leave `Archive` eligible. The inline converter should retain its existing independent scope behavior.

7. **Single-tag counting.** Prepare notes with one frontmatter tag, one inline tag, repeated tags, the same tag in both places, case variants, two distinct tags, and explicit `#work` plus `#work/meetings`. Only the first five qualify as one distinct tag. Test tags inside code, HTML comments, `%%` comments, and non-tag frontmatter properties; those must not add to the count. `#work #abc` must count as two even if the converter's hex filter is on. `#2024` in body text is not an Obsidian tag. Malformed frontmatter should be reported and skipped.

8. **Paths and capitalization.** Preview root-level notes, notes already directly in the matching folder, and a note tagged `#work` inside `work/archive/`. Verify existing `Work/Meetings` capitalization is reused. Test `#work` and `#WORK` in different notes when the folder is missing; the preview should choose one spelling for the batch. On a filesystem that supports it, ambiguous case-only folder variants must be skipped. Reserved names such as `CON`, invalid tag paths, and a file occupying a needed folder path must be reported without changes.

9. **Filename conflicts.** Put a same-named note in a destination and create two source notes with the same filename and tag. Preview must skip the existing conflict and every member of the shared-destination group, including case-only filename differences. Nothing should be overwritten, merged or renamed automatically. For a new NN note, a conflict should produce a notice and retain the note at its original location.

10. **Both backup warnings, through both entry points.** Use the command palette and settings **Preview moves…** button. Confirm the sequence preview → first vault-backup warning → second vault-backup warning → processing. Cancel the preview and each warning independently, then repeat using Escape and clicking outside the dialog. Confirm no folders, moves or run logs appear before both warnings are accepted. The first acceptance alone must do nothing. A new run must ask twice again; a zero-candidate preview must not proceed.

11. **Preview export and edits.** Export a preview and check its source/tag/destination/reason rows in the plugin directory. While either warning is open, edit a candidate's body, add another tag, rename or delete the file, change exclusions, or create a destination filename conflict. After acceptance, affected notes must remain in place or be reported unavailable; no unpreviewed destination may replace the one shown. Verify the summary/log explains skipped or failed attempts.

12. **Links and attachments.** Test incoming wikilinks and Markdown links, outgoing relative links, embeds, and attachments after moves. Check Obsidian's automatic internal-link update setting both on and off. The plugin uses Obsidian's move operation and follows that preference; verify the actual results. Attachment files and empty source folders should remain where they were. Do not rely on unchanged modification timestamps for moved notes.

13. **Progress, cancellation and recovery.** Run a batch large enough to cancel mid-run. Verify completed moves stay completed, remaining notes stay unprocessed, and created folders remain. Inspect the new `folder-moves-*.jsonl` log: plan, per-note `moving` and final outcomes, then summary. The latest result for a source path is authoritative; a final `moving` record requires inspecting the actual file locations. Rerun and confirm already-correct notes are skipped. In a disposable environment, simulate a read-only/failed log write and verify further moves stop.

14. **Concurrency and reload.** While a manual preview or conversion is open, try starting the other manual tool; only one operation may run. Disable the plugin while its final move warning is open and then accept it; no work should start. Disable/re-enable the plugin and create one NN note; verify there is only one move attempt and no duplicate notices.

15. **Desktop, mobile and sync.** On the actual devices/service, create a note on device A and let it sync to device B with another Navigator selection. Background synchronization and ordinary startup must not move notes on B. Test locally opening newly synced notes, especially within 30 seconds with the same selected tag: Obsidian supplies no origin-device ID, so that case can qualify for filing. Verify editor stability, template timing, offline/reconnect behavior, and absence of repeated moves. Turn automatic filing off on devices where this bounded detection is unsuitable.

16. **Converter regression.** Run the existing inline-to-frontmatter converter with its usual scope, preview/export, both backup warnings, filters and existing-tags-only mode. Check that it still writes tags only when manually requested and that folder cleanup leaves frontmatter and inline tag text intact, except for any link updates performed by Obsidian.

17. **Drop a single-tag note.** Put `note.md` in `work/` with only `#work`. Drop it onto `#personal` in Navigator. It must immediately retain only `#personal` and move to `personal/note.md`, without a dialog. Repeat with inline-only, frontmatter-only, both, repeated/capitalized tags, an untagged note, and `#personal/meetings` with missing folders. Check incoming/outgoing links and the open editor. A note already in the destination must still have its tags replaced. The new-note filing toggle can remain off.

18. **Multi-tag decisions.** Drop a note with `#work` and `#home` onto `#personal`. No tags, folders or note paths should change before a decision. **Yes** must keep only `#personal` and move it; **No, just add the tag** must retain both original tags and location. Escape, clicking outside and closing must cancel that note without adding the tag. Count a tag split between properties and body as one distinct tag; count explicit parent and child tags as two. Code, comments, other properties and escaped hashes must survive removal. Check real YAML lists, strings, capitalized/legacy tag fields, BOM and CRLF files; YAML formatting/comments may change when properties are rewritten.

19. **Saved defaults.** Check the checkbox with each answer in separate runs. Verify the next multi-tag drop uses the chosen behavior without a prompt, the preference survives reload, and the settings dropdown matches. Manually select all three defaults, including resetting to **Ask every time**. A single-tag note must still switch and move automatically even with **Just add the tag** saved. Turn tag-drop filing off and verify Navigator's usual additive behavior returns.

20. **Drop protection and changes while waiting.** Try excluded sources/destinations, a conflicting filename (including case variants), a file occupying a folder path, and reserved folder names. Existing tags must remain and the target tag may only be added, with no move. While a prompt is open, edit, rename or delete its note, change exclusions, or create a destination conflict. Stale decisions must not overwrite edits or remove tags. Where practical in the test environment, deny the final rename and confirm the original content is restored; later edits must never be overwritten during recovery.

21. **Multiple notes, windows and cleanup.** Drag several notes at once, mixing zero, one and multiple tags. Prompt for each multi-tag note until a choice is saved; then use it for the remaining notes. Verify each note is handled once, including on macOS and between main/pop-out windows. Repeat drops, close a pop-out, reload/disable the plugin with a dialog open, and check that there are no duplicate dialogs, stuck drag highlights or late edits. Disabling the feature should close a pending dialog. Manual tools must not start during a pending drop; during a manual tool, drops retain Navigator's native behavior. Folder/property targets, tag-tree reorganization, Tagged/Untagged, attachments and external-file drops must retain native behavior. Ordinary tag edits and sync must never trigger refiling.

22. **Select the destination tag after filing.** With a single-tag note selected/open, drop it onto another tag and confirm the destination tag becomes highlighted in Navigator after the move. Repeat with a nested tag whose parents are collapsed, an existing destination folder, a folder created by the move, and a multi-tag note using **Yes**. Test Navigator's auto-reveal setting on and off, a multi-note drop, and a pop-out window. Check that selecting the tag stays stable after the UI settles. **No, just add the tag**, cancelled dialogs, exclusions and failed moves must not request new navigation. Disable filing or unload the plugin during a pending move and confirm there is no delayed tag selection.
